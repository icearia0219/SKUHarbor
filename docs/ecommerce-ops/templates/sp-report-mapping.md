# SP 固定导入模板 v1

这些 CSV、XLSX 和 metadata JSON 全部是合成演示数据，不来自真实账户，也不代表任何官方站点默认归因窗口。必须由操作人员从实际报表确认窗口、可见延迟及 advertiser_type，未知值填写 `null`。

导入时人工明确选择 `sp-campaign-v1` 或 `sp-search-term-v1`，同时提供对应 metadata；文件内容必须保持给定的英文列名与顺序。实际 Amazon 导出若不同，先由人工明确映射到模板，系统不使用模型猜字段。只支持 SP，货币仅 USD/EUR，金额为点号小数且最多两位，不带币种符号或千分位；整数栏不接受指数或小数。

XLSX 仅接受一个带字符串日期的 values-only 工作表，不接收公式、外部关系、宏、嵌入对象及自动Excel日期序号转换。文件上限5 MiB，展开上限10 MiB。CSV 可以有引号字段；证据定位使用从1开始的记录行（包含标题与空记录），XLSX 使用工作表行。

metadata 必须记录工作区、账户、站点、币种、IANA时区、SP、seller/vendor、归因窗口天数、数据可见延迟天数、粒度、含首尾日期范围、带时区的生成时间及 provenance。`daily` 行日期必须在范围内；`summary` 行日期留空，期间由metadata表达。日期字段不能推导或改变站点/SKU。

同一天的活动汇总和搜索词明细不能相加。搜索词粒度包含活动、广告组、搜索词、Targeting及Match Type；相同维度但不同值的行是冲突，需人工解决。完全相同粒度/值的重复行可去重；不同日期、活动、广告组或投放维度不会合并为重复。只有期间汇总的重叠报告不可拆分去重，必须阻断。

成熟度同时要求 as_of 与报告实际生成时间，在报告时区均超过完整报告结束日、归因窗口及数据可见延迟。早期导出的静态文件不会因为后来等待而自动变成成熟数据；应重新获取报表。未知窗口/延迟时保留描述统计、成熟度 unknown，不直接建议否词或停投。

金额存储单位为分，ACoS/CTR/CVR为ratio，CPC为分；先加分子分母，再算比例。零分母为null并记录原因；CVR以订单数为分子。没有同日期/粒度的业务总销售不计算TACoS，不相加广告归因销售与业务销售，不相减声称精确自然销售。环比要求等长、不重叠、成熟且口径一致，声明季节/促销/库存等差异及非因果限制。
