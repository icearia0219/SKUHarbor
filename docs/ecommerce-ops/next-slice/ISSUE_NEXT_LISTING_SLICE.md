# Issue：让一个真实 SKU 完成可见、可审核的 Listing 闭环

日期：2026-11-13。状态：依据交付证据提出的下一轮需求，不是已实现变更。配套：[Plan](PLAN_NEXT_LISTING_SLICE.md)、[审阅报告](REVIEW_ECOMMERCE_2026-11-13.md)。

## 1. 当前问题与证据

当前是可运行的本地电商工作台/流程初版，原定整体工程/演示验收尚未通过。证据包没有完整源码、输入/gold及截图，因此本Issue针对可核实的产物问题提出改进，代码根因需在实际仓库确认。

- A25/60与B21/60可复算，但通过结果分别含24和18个needs_input。task_status=waiting_review总量仅A1、B3；Listing两组均0/15待审。不能将A Listing10/15说成10份可用Listing。
- B `test-travel-kettle-listing`的1650W/230V与证据一致，但claim原文和标题文本不一致；这是定位契约错误，不能当规格幻觉。
- B `test-slot-toaster-listing`本案实际只有120V、没有已确认功率；它仍输出draft并把功率列为未检查/可选，评分期望needs_input。这暴露必需性和分支错误，不能拿其他广告案例中的850W跨案证明本案已有功率。
- A的7个广告包全部补料，B有5个draft但被质检拦截；需区分必需事实、可省略信息与查询关注点，不能一律靠增加提示词解决。
- 客服否定句被误标完成/到账，亦存在无凭证“已转交”的真实错误和漏报。该问题单独登记，不为本轮Listing交付扩大到全面重做客服。
- 产品报告自述：默认仍进入普通聊天，业务页独立，手机入口不明显，缺首个任务引导。本轮不宣称已经独立看过UI。

## 2. 本轮唯一业务目标

一个运营人员在普通入口能发现电商功能，为**一个真实SKU、一个站点**导入资料，确认事实，生成有证据、能送审的Listing，修改后审核导出；更改事实时旧审批失效。

优先用US/en-US作为工程验证范围（已有US正例检索记录），若实际使用者只能核对DE，则改为DE/de-DE并先补该站适用规则及检索正例；此选择写入启动记录。另一个站点保留原功能但不并行扩展，不把本站通过泛化为两站通过。

演示与真实SKU分开；没有真实资料时只能完成工程路径，真实交付保持blocked。一次真实闭环不等于整体A通过或五工作日试运行完成。

### N03的最小设计

1. 沿用或兼容现有selector语法，先在源码确认；选定一种规范写法并在schema描述、prompt、示例、validator、scorer中一致实现。不要未经迁移直接破坏历史结果。
2. 文字claim只指向具体字符串，例如标题或第1条bullet，不指向整个数组、对象或数字。路径错误与文本不匹配分别返回原因及目标类型。
3. 明确“展示片段”与“事实支持”两层：前者保证引用指向用户看到的文字；后者核对source_id、typed value/unit、站点与已确认事实。德语词序或标点不一致不能自动当规格无依据。
4. 指标数字继续由metrics_ref与源行追溯，不能要求一整段中文必须出现在数值117里；此次只加必要兼容/回归，不重构广告业务。
5. 不允许用宽松语义匹配自动批准任意文字；修正定位误报后仍须阻断错误SKU、错误数值/单位、虚构认证与无效证据。

### N04的规则

- 规则字段的requiredness必须有来源/明确的任务要求，不从简短政策的提及或搜索query推测。
- 输入中不存在/未确认必需事实→needs_input；输入已确认但模型漏写必需值→生成质量错误，在既有预算内有界修正或blocked，不能让用户重复补同一资料；事实冲突→请求确认；可选卖点没证据→省略并说明，不迫使整份草稿空白。
- 规则未知或覆盖不全应保持原有禁止“已完整平台检查”声明，不能为了出稿伪造官方profile。
- 数据集gold认为应出稿而现有输入确实不足时，先审输入/gold，不把模型正确补问硬改为错误。旧评分不覆盖；必要修订作为新数据版本。

## 4. 不做什么

- 本轮不接SP-API/Ads API、竞品采集、新向量库、新模型网关、新调度器或微调。
- 不扩充五个模块并行优化，不重做全部客服/广告，不把现有未完成项悄悄标完成。
- 不做普通聊天的全自主电商调度。本轮只提供明确入口/任务向导，现有聊天行为保留。
- 不放开平台写入、模型自批、未审正式导出，不删除安全/事实校验以换分。
- 不把“正确拒答”“schema合法”“生成draft”“待审核”“人工通过”“导出成功”算同一种成功。
- 不继续把已看过的60案当未见封存集；不在新gold里写入模型输出使之过线。
- 不自动删除被平台阻止清理的凭据副本，不反复重试绕过拒绝。遗留由本机持有人按原有允许流程处置并记录，文件内容不得进新交接包。

## 5. 输入和责任

- 用户/业务人员：提供一个SKU的规格、说明书或文本、当前Listing、对应站点规则及权威依据；确认哪些字段是必需，核对语言与业务表述。
- Codex：先查真实源码/版本，审开发集失败分类，实现最小修复、UI入口和引导、测试、保存运行证据。
- 评测复核者：审阅新gold的状态/字段/证据与requiredness；无法获得真人复核时标为工程/合成验证，不称真实质量验收。
- 模型/部署管理员：在允许环境提供后端配置；不把密钥写入文档或对话。真实模型缺凭证时如实阻塞，不用合成provider冒充。

## 6. 验收（新局部里程碑，不替代原整体A/B/C）

### 工程与用户体验

- 目标设备主入口可发现；给1名未参与实现的使用者从正常首页开始，不提供隐藏URL，在5分钟内完成找到入口、选SKU/站点并进入导入向导。保留观察记录；单人结果只证明该次检查。
- 可读CSV/JSON/文本是本轮保证链路；PDF依赖缺失时预检明确报出，不接收文件后假成功。若用PDF完成真实闭环，必须补pdftotext安装及可读/扫描件测试。
- 至少一次真实模型运行到待审，人工审核后正式导出；旧事实/规则变化、改稿、重复请求、跨工作区等原有守卫仍通过。

### 质量

- 开发集12个定向对照：6个有据正例（原文/单位/德语改述等）与6个真实错误反例（错SKU、错数值/单位、假认证、无效证据等）；全部按预期通过/阻断。不得仅消除误报而增加漏报。
- 新封存集20案，至少10个完整资料正例、10个应补料/阻断反例；至少10个新产品家族，同家族只在同一分区；不进入调参或prompt示例。
- 正例至少8/10进入待审且应有字段100%覆盖；反例10/10正确分支；严重事实错误0。报告每案、计数和样本相关性，小样本不宣称普遍≥80%。
- 事实证据可定位100%；已知必需参数值/单位100%正确；证据支持需按业务标签复核，不用词法flag替代。
- 完整资料生成成功率、正确补料率、实际人工通过率、修改用时分别报告；只比较同一输入条件，不把新补的资料当模型方法提升。

### 真实单SKU演示

`正常首页 → 电商入口 → 导入 → 确认事实 → 生成 → 查证据/修改 → 审核 → 导出 → 改参数 → 旧审失效`。

保留输入hash、代码commit、模型/prompt/规则/质检版本、真实模型调用、产物及人工复核；不能复用已批准的合成产物当此次真实成功。
