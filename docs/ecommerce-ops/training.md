# 电商运营工作台使用与审核培训

工作台位于登录后的 `/ecommerce-ops`。管理员开启 `OPENDOT_ECOMMERCE_OPS=true` 后显示入口；关闭或无法确认可用性时，入口隐藏，直达页面也不显示写入表单。原有聊天仍是默认入口。

当前业务站点是 Amazon US（en-US / USD）与 DE（de-DE / EUR）。SP-API、Ads API 尚未接通；文件导入成功不等于平台连接成功。工作台生成内部草稿和诊断建议，不提交 Listing、不修改广告、不执行退款/补发，也不发送客服消息。

## 1. 先选工作区，再处理一个站点的资料

工作区选项来自现有授权工作区列表。选择真实工作区后，产品、原文、知识、任务和审核按该工作区保存。相同 SKU 在 US 与 DE 的产品与规格分别管理，不能把一个站点的规格当成另一个站点的事实。

浏览器切换工作区时会清空旧视图，并忽略晚到的旧请求。遇到资源不存在或权限错误，应返回授权工作区，不能通过替换 ID 尝试引用他人的资料。

## 2. 产品页：导入来源，逐项确认事实

1. 填写 SKU、站点、产品类型与卖家适用范围，添加产品。
2. 选择关联产品与资料类型，导入 CSV / JSON / 文本 / 可读 PDF / DOCX；广告报表另支持 XLSX。填写来源版本、数据来源和使用授权说明。
3. 核对导入问题与坏行。扫描件、空文本、不支持的格式或错误列不能当作成功抽取。
4. 打开产品详情，检查候选事实的字段、具体值、单位与证据。选择一个原始候选值，填写理由，再确认或拒绝。
5. 需要更正规格时，导入新来源，再确认对应证据。不能直接修改候选值来制造来源中没有的事实。

导入只生成候选事实，不会自动认可。两个已确认值冲突时，需要人工裁决，不能让模型自行选一个。竞品认证和经验不能证明本品功能。原文件通过授权下载读取，证据按钮读取当前工作区可访问的证据位置。

## 3. 知识页：记录适用性和版本

先在产品页导入政策或品牌资料，再登记同站点资料的知识标识、产品类型、卖家范围、来源权威、审核状态、版本和有效期。

只有经过业务核验的真实官方资料才应标记为官方规则。制造商、商家与经验资料应保留各自来源身份。知识沿用原始文件的来源类型与 SKU 范围，不能通过入库把竞品资料改为本品或官方规则。

未知生效时间或不明有效期要明确保留，不能以文字相似度代替适用性核验。使用“更新此知识版本”时提交当前 revision；版本冲突需要刷新、核对他人的更新后再操作。不要用新记录掩盖冲突的旧记录。

## 4. 任务页：按问题选择任务

| 任务                        | 应准备的资料                                   | 应核对的结果                                                  |
| --------------------------- | ---------------------------------------------- | ------------------------------------------------------------- |
| 候选研究 `research_brief`   | 授权候选资料、目标、比较标准；可选多个产品     | 候选差异、缺失证据、后续问题，不把评分当成销量或利润预测      |
| Listing 内容 `listing_pack` | 单个站点/SKU 已确认事实、适用政策与品牌资料    | 标题、卖点、描述、搜索词、声明证据、未检查规则                |
| 广告文案 `ad_pack`          | 单个站点/SKU 事实、广告位置与适用规则          | 文案方案和候选词来源；不能借已审 Listing 自动批准新增声明     |
| 广告诊断 `ads_diagnosis`    | 已导入并核对口径的广告报表                     | 金额单位、分子分母、原始 ratio、归因成熟度、源行与缺失上下文  |
| 客服草稿 `support_draft`    | 单个产品、脱敏工单、必要订单信息与适用商家政策 | 回复草稿和需人工处理事项；没有有效回执时不能声称已退款/已补发 |

Listing、广告文案和客服草稿一次选择一个产品；研究可以多选。任务要求、附件与报告时间可进一步限定输入。创建任务后查看服务端状态；排队、生成、质检、等待审核、补料、阻断和失败都不能显示为已交付。

### 广告报表口径

当前列映射为 `sp-search-term-v1` 与 `sp-campaign-v1`。选择实际文件后，核对站点/币种、账户、IANA 报告时区、广告主类型、每日或汇总粒度、日期窗口、报告生成时间、归因窗口和报告延迟。

未知归因或延迟天数留空，保留为 null。不同币种、时区、窗口或重复粒度不能硬合并。订单数与件数有不同含义。界面展示服务端计算的结果，不重算金额或比例；ratio 为空时显示未知/不可计算，不显示成 0%。归因未成熟时不能据此直接否词或停投。

### 补料与恢复

补充或更正产品事实、规则与附件后，点击任务记录中的“补料后恢复”。服务端决定是否有新输入：新输入形成新的 input_revision 与独立产物，旧产物仍可预览；重复恢复相同输入不应重复生成。暂停和取消属于执行控制，不等于平台业务操作。

## 5. 审核页：审核确切版本，区分预览与交付

1. 打开产物，检查状态、内容 revision、Hash、输入版本与规则快照。
2. 逐项阅读内容、声明到字段的位置、证据原文和未检查项。广告诊断还要核对币种、分子分母、源行与成熟度。
3. 需要改稿时使用结构化字段编辑。保存会更新版本、撤销旧审核并重新质检；等待新版本返回前不能正式导出。
4. 填写审核理由后，通过审核或退回修改。审核记录由服务端保存，模型不会输出 approved。
5. 未审或 stale 产物只做预览导出；有效审核版本才允许正式导出。JSON / Markdown 与广告 CSV 使用同一服务端快照，下载时再次校验 revision 和审核。

“已失效”表示当前输入或规则已变化，旧审核不能继续用于交付。关闭审核抽屉或刷新不会代替审核。若界面仍在等待新版本，请刷新后确认，不能绕过禁用按钮。

后续跟进可关联到现有工作目标，必须填写验收条件和时间。当前跟进需手动推进，不会自动运行广告或客服操作，也不会自动批准后续产物。

## 6. 失败与成本怎么读

| 情况                               | 处理方式                                             |
| ---------------------------------- | ---------------------------------------------------- |
| 事实冲突、政策过期、适用性未知     | 先检查具体问题和来源，补充或裁决后恢复               |
| 行错误、映射错误、空抽取           | 更正文件或使用当前模板，保留原始坏行定位             |
| revision / Hash 冲突               | 刷新最新版本，重新核对后提交，不能覆盖他人的更新     |
| 模型不可用、输出无效、超时、超预算 | 检查现有模型配置与额度；不要连续重复点击创建大量任务 |
| Token 或费用未知                   | 按未知记录；未知费用不能填 0，也不能据此声称更便宜   |
| 订单归属、退款或补发回执缺失       | 补充授权证据或转人工；只保留草稿，不声称执行完成     |

## 7. 数据流向与培训练习

原始字节、提取文本、来源元数据、证据与业务对象保存在既有 SQLite 的电商表中，受工作区授权控制。模型使用当前配置的 provider，可能把必要的冻结事实和证据片段发送给外部模型服务；客服上下文在进入模型前经过最小化与脱敏。原文是不可信资料，不能作为读取密钥、退款或越权操作的指令。备份和恢复应使用项目现有数据库流程，参照部署文档操作。

培训练习应先使用标记为 synthetic 的虚构 SKU、规则、报表和工单。要求操作者亲自完成一次冲突裁决、一次改稿后的重审，以及一次 unknown 成本解释，再由业务审核人核对记录。

离线练习可直接运行 `node scripts/ecommerce-demo.mjs --workspace demo-training --reset --scenario launch-us-de`。演示只操作 `artifacts/ecommerce-ops/demos/demo-training/` 下带 marker 的私有 SQLite 和导出目录，模拟人工身份明确为 `synthetic.operator`；这不是生产工作区或真实业务审核。已有演示去掉 reset 可验证持久结果和导出 hash。更多场景、reset 边界及 `ecommerce-check` 命令见 [demo.md](demo.md)。

截至本次交付，浏览器证据来自隔离 SQLite、本地合成 provider 和虚构资料：Listing 的 US/DE 流程、US 冲突恢复、US 广告边界与 US 客服草稿已通过三条浏览器测试。它不代表研究/广告文案的全部 UI 验收、真实模型质量、真实 Amazon 规则核验、五工作日业务试用或经营收益。完整状态以 [验收记录](acceptance.md) 为准，演示见 [demo.md](demo.md)。
