# 运营 SOP v1

1. 登录已有 OpenDot，选择自己的工作区、US/en-US 或 DE/de-DE；Listing、广告文案、客服每项只选一个SKU，候选比较可多选。
2. 上传授权资料，填写provenance、市场、权属说明和观察时间。候选规格不会自动确认；逐项查看原文，给确认/驳回理由。冲突先补料，竞品认证不能背书本品。
3. 登记规则的类别、权威、市场/商品类型/卖家、有效期与审核状态。规则先过滤再检索，经验仅作建议。未知适用性不能冒充当前政策；导入PTD仍须披露未检查的Amazon扩展与卖家条件。
4. 选择五类任务，冻结输入版本。广告只接固定模板/明确映射，检查日期、币种、粒度、账户、归因窗口及成熟度。零分母显示不适用，订单数不是件数，不合并重复期间或活动与搜索词汇总。
5. 检查草稿、每条声明及证据、规则覆盖和未检查项。模型格式错误仅有界修复，截断/超时/额度失败如实保留。客服只给草稿，申请退款不是退款完成，危险/归属不明转人工。
6. 人工编辑后重新质检、审核，审核绑定确切版本和内容hash。事实或政策改变会使相关旧稿stale；恢复补料任务会创建新输入版本和新成果，旧稿仍保留。
7. 无审批仅能导出明确的未审预览；已审包也只是内部交付物，不是平台上传payload。JSON/Markdown/广告CSV共用一个结果模型。原文与导出均需原工作区授权。
8. 将重要缺口关联人工Goal，注明截止和证据完成条件，手动推进。Goal完成不自动批准草稿，也不发送/退款。

经营效果记录需真实产品/规则、脱敏报表/工单以及业务复核；合成演示和离线测试不代表销量、利润或节省工时。按模块及站点分别留验收，不用一个模块的成功替代其他模块。
